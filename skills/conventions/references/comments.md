# Comments

## Rule

1. **Comment why, not what** — a constraint, a trade-off, business logic that is not obvious.
2. **Self-explanatory code gets no comment.** A comment that restates the code, the platform or the
   callee's own documentation is deleted.
3. **A capability without a common usage pattern** gets a short usage comment on its `api` surface
   only.
4. **A stale comment is fixed or deleted with the code it describes.**
